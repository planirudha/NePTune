Instructions for Writing Programs Based on Scene Descriptions

You will be asked to write Python programs to answer questions about a visual scene. 
Use only the specified functions and adhere to the following guidelines.

--- Available Functions and Usage Guidelines ---

1. **Score Generation with `score`:**
   - **Purpose:** Determine if objects have certain properties or relationships.
   - **Returns:** Scores [0-1] for all objects in the scene for the question asked.
   - **Syntax:**
     result = score(question, num_objects)
   - **Parameters:**
     - **question (str):** The question to pose to the model.
     - **num_objects (int):** The number of objects involved (1 or 2).
       - **1:** A question about the main object. If you use bounding box ask a question about the object in the **red bounding box**. Returns a 1D vector.
       - **2:** A question involving objects inside of the red and green bounding boxes. The red box is the reference object coming first. Returns a 2D vector where `row[i][j]` represents if object `i` (red bbox) has the relation with `j` (green bbox). The diagonal (where `i=j`) is always 0 to ensure mutual exclusivity of the variables (an object cannot have a relation with itself). 
   - When asking for properties, You must mention the class of object. "Is the animal inside of the red bounding box brown?"
   - When asking for relationships,you must mention the class of object.
    - Use relationships for comparing object atrributes such as colo, size, shape etc. 
    - "Is the animal inside of the red bounding box bigger the animal inside of the green bounding box?"
   - When asking for an object given the image "context", just mention the "main object". "Is the main object inside of the red bounding box in the middle of the scene?"
  Concept tightness rule
  1. When you define a concept with `score`, the question string must describe the full concept you need for reasoning, not a weaker or more general property.
  2. If the question asks about “the smallest cylinder”, you must not define a predicate for “the smallest object” and later intersect it with “cylinder”.
  3. Instead, either:
    a) Ask directly for the full concept:
        `is_smallest_dog = score("Is the main object in the red bounding box the smallest dog in the scene?", num_objects=1)`
        `smallest_dog = is_smallest_dog("x1").iota("x1")`
        or
    b) Define all needed properties declaratively and keep each predicate as tight as possible:
        `is_dog = score("Is the main object in the red bounding box a dog?", num_objects=1)`
        `is_smallest_among_dogs = score("Is the main object in the red bounding box the smallest dog in the scene?", num_objects=1)`
        `smallest_cylinder = (is_dog("x1") & is_smallest_among_dogs("x1")).iota("x1")`

2. **Spatial Relation Concepts**:
   - Use predefined `left_of`, `right_of`, `above`, `below`, `distance` and `closeness` for spatial relations.
   - These functions return a 2D vector with an identity mask. The red bounding box is the reference object and the green bounding box is the target object.
   - **Example:**
     ```python
     left_of("x1", "x2") # Returns a 2D vector of {0,1}
     right_of("x1", "x2") # Returns a 2D vector of {0,1}
     above("x1", "x2") # Returns a 2D vector of {0,1}
     below("x1", "x2") # Returns a 2D vector of {0,1}
     behind("x1", "x2") # Returns a 2D vector of {0,1}
     front("x1", "x2") # Returns a 2D vector of {0,1}
     
     distance("x1", "x2") # Returns a 2D vector of normalized scores of distance of x1 from x2 the more an object is far the more the score is close to 1
     closeness("x1", "x2") # Returns a 2D vector of normalized scores of inverse of distance of x1 from x2 the more an object is close the more the score is close to 1
     between("x1", "x2", "x3") # Returns a 3D vector of {0,1} # X1 between x2 and x3
     
     ## Use the below if you are looking for right most or left most
     left_of_normalized("x1", "x2") # Returns a 2D vector of normalized scores of x distance of x1 from x2 the more an object is to the left the more the score is close to 1. Objects to the Further to the left get higher score.
     right_of_normalized("x1", "x2") # Returns a 2D vector of normalized scores of x distance of x1 from x2 the more an object is to the right the more the score is close to 1. Objects to the Further to the right get higher score.
     above_normalized("x1", "x2") # Returns a 2D vector of normalized scores of y distance of x1 from x2 the more an object is above the more the score is close to 1. Objects to the Further above get higher score.
     below_normalized("x1", "x2") # Returns a 2D vector of normalized scores of y distance of x1 from x2 the more an object is below the more the score is close to 1.  Objects to the Further below get higher score.
     behind_normalized("x1", "x2") # Returns a 2D vector of normalized scores of z distance of x1 from x2 the more an object is behind the more the score is close to 1.  Objects to the Further behind get higher score.
     front_normalized("x1", "x2") # Returns a 2D vector of normalized scores of z distance of x1 from x2 the more an object is in front the more the score is close to 1.  Objects to the Further in front get higher score.

     ``` 
   - Use the combinations of these for new spatial relations.

3. **Querying with `query`:**
   - **Purpose:** Retrieve specific textual information about an object.
   - **Returns:** A string answer for the question mentioned in the query (It may include reference to the red bounding box). 
   - **Syntax:**
     answer = query(question:str, object_id:Optional[int])
   - **Parameters:**
     - **question (str):** The question to ask.
     - **object_id (int):** The identifier of the main object, typically obtained from `argmax()`. If not passed asks about the holw image
   - Warning: Since the output is undeterministic don"t use string equality
   
4. **Declarative Composition Operations:**
   - Use `&` or `and_op` for logical AND, `|` or `or_op` for logical OR, and `~` for logical NOT. 
   - Do not use Python"s `and` or `or` for probabilistic/score-based functions.
   - In composition you can assign **string** variables to predicates. The default variable names follow the pattern `["x1", "x2", ..., "xk"]` where `k` is the number of dimensions (e.g., `x1` for 1D, `x1, x2` for 2D).
   - **Composition Rules:**
     - 1D concept composed with a 1D concept returns a 1D vector of the composed concept.
     - 2D concept composed with a 1D concept returns a 2D vector of the composed concept.
     - For composing more than two predicates use the `or_op` or `and_op` function
   - **Examples:**
     <code>
     is_cat = score("Is the main object in the red bounding box a cat?", num_objects=1)
     same_shape = score("Is the main object in the red bounding box the same shape as the main object in the green bounding box?", num_objects=2)
     is_black = score("Is the main in the object red bounding box black color?", num_objects=1)

     # Apply iota to normalize the concept before using it in relations
     is_black_cat = (is_cat("x1") & is_black("x1")).iota("x1")
     same_shape_as_black_cat = same_shape("x2","x1") & is_black_cat("x1")
     </code>
   - **Important:** 
     - Do not use `argmax` and indexing for composing relationships with properties.
     - If you already used a concept in a `query` function, do not compose it again with the results of that same query. 
       (e.g., avoid: `apple_behind_large_pineapple & is_large_pineapple` → separate them properly).

   - **Another example:**
     <code>
     # "blue circle same size as a red circle"
     # Apply iota to normalize the concepts
     blue_circle = (is_blue("x1") & is_circle("x1")).iota("x1")
     red_circle = (is_red("x1") & is_circle("x1")).iota("x1")
     
     same_size_as_red_circle = same_size("x1","x2") & red_circle("x2")
     blue_circle_same_size_as_red_circle =  same_size_as_red_circle("x1","x2") & blue_circle("x1")
    </code>

5. **Imperative reasoning*
  Python code enables us to reason over concept scores with Python operations such as loops and conditionals.

  There is a strict priority:

  1. Concept scoring with `score`, `left_of`, `right_of`, etc.
  2. Declarative reasoning with `&`, `|`, `~`, `.exists`, `.forall`, `.count`,`.implies` or `.iota`.
  3. Imperative reasoning with Python loops and conditionals.

  You must prefer declarative reasoning whenever it can express the solution.

  Use imperative reasoning **only** when the question requires:

  1. Collecting or manipulating sets of free form text returned by `query` (for example, building a `set` of colors).
  2. Returning a data structure that cannot be expressed declaratively.

  You must not use Python loops to:

  1. Implement selection over objects when you can use `.iota`, `.exists`, `.forall`, `.count`, `implies` or `argmax`.
  2. Compose properties and relations that can be written with declarative operators.
            
6. **Existence and Counting:**

  **6.1 Existence (`.exists()`):**
  The `.exists()` operator checks for the existence of objects satisfying a condition. It reduces the dimensionality of the predicate.
  
  - **Scalar Existence (No arguments):**
    - `P.exists()` checks if the condition `P` holds for *any* combination of its variables.
    - **Returns:** A scalar score (0-1) representing the truth value (Boolean-like).
    - **Usage:** Use this for Yes/No questions about the entire scene.
    - **Example:** `(is_red("x1") & is_blue("x2") & left_of("x1", "x2")).exists()` -> Returns scalar (True if any red object is left of any blue object).

  - **Projected Existence (With arguments):**
    - `P.exists("var")` eliminates `"var"` from the predicate by checking if *at least one* value of `"var"` satisfies the condition for the remaining variables. It projects the predicate onto the remaining variables.
    - **Returns:** A tensor with `"var"` removed.
    - **Usage:** Use this to filter objects based on their relationships with others.
    - **Example:** `(is_red("x1") & is_blue("x2") & left_of("x1", "x2")).exists("x2")` -> Returns a 1D tensor over `x1`. It represents "x1 is red AND there exists some blue x2 to the right of x1".

  **6.2 Counting (`.count()`):**
  Counting sums up the scores of objects satisfying a predicate.
  
  - **Scalar Counting (No arguments):**
    - `P.count()` sums the scores over *all* variables.
    - **Returns:** A single number (scalar).
    - **Usage:** Use this to count the total number of tuples satisfying `P`.
    - **Example:** `is_red.count()` -> Total number of red objects.

  - **Grouped Counting (With arguments):**
    - `P.count("var")` sums over all variables *except* `"var"`. It preserves `"var"`.
    - **Returns:** A tensor indexed by `"var"`.
    - **Usage:** Use this to count how many *other* objects relate to each instance of `"var"`.
    - **Example:** `left_of("x1", "x2").count("x1")` -> For each `x1`, count how many `x2` are to its right.

  - **Comparing counts:**
    - You can compare counts using `>`, `<`, `==`. For example:
      `more_red = is_red.count() > is_blue.count()`.

  - **Interaction with `iota`:**
    - Do not call `.count()` on a predicate after applying `iota` if you want the actual number of objects. `iota` normalizes scores into a distribution and removes cardinality information.

  - **Using `exists` and `count` together:**

    The correct pattern is:
    1) Use `exists("var_to_remove")` to eliminate the inner variable and create a unary predicate over the outer variable.  
    2) Then call `count()` on that unary predicate.

    Example 1: count how many objects are right of a red circle.
    ```
    is_red = score("Is the main object in the red bounding box red?", num_objects=1)
    is_circle = score("Is the main object in the red bounding box a circle?", num_objects=1)
    red_circle = (is_red("x2") & is_circle("x2")).iota("x2")

    # unary predicate over x1: "x1 is right of some red circle x2"
    right_of_red_circle = (right_of("x1", "x2") & red_circle("x2")).exists("x2")

    # final scalar count
    return right_of_red_circle.count()
    ```
    Example 2: count how many red objects have some bigger blue object to their right.
    ```
    is_red = score("Is the main object in the red bounding box red?", num_objects=1)
    is_blue = score("Is the main object in the red bounding box blue?", num_objects=1)
    bigger = score("Is the main object in the red bounding box bigger than the object in the green bounding box?", num_objects=2)

    # Normalize the blue object concept
    blue_obj = is_blue("x2").iota("x2")

    # unary predicate over x1: "x1 is red and there exists x2 that is blue, bigger, and right of x1"
    has_bigger_blue_right = (
        is_red("x1") &
        (blue_obj("x2") & bigger("x2", "x1") & right_of("x2", "x1"))
    )

    # number of such red objects
    return has_bigger_blue_right.exists("x2").count()
    ```
7. **Selection with `iota` (Soft Selection for Definite References):**
  Use `iota` to model definite references like "the cylinder", "the red cube", "that sphere", or "the leftmost cube".

  **7.1 Semantics:**
  - `iota` performs soft selection by normalizing scores.
  - **Unary Predicate `p("x1")`:** `p.iota("x1")` normalizes scores across objects, behaving like a soft "there exists such an x1" while remaining a predicate over `x1`.
  - **Binary Relation `r("x1", "x2")`:** `r.iota("x1")` softly aggregates over `x2` and normalizes over `x1`.

  **7.2 When to use `iota`:**
  - **Definite References:** Use `iota` for "the X", "that X", "the leftmost X".
  - **Indefinite References:** Do NOT use `iota` for "a cube", "any sphere", "some object". Use plain predicates with `exists` or `forall`.
  - **Counting:** Do NOT apply `iota` to concepts you are going to count.

  **7.3 How to use `iota` in code:**
  - **Rule:** Always call `iota` with a variable name and assign it to a *new* variable. Do not overwrite the original predicate.
  
  *Correct Pattern:*
  ```python
  is_cylinder = score("Is the main object in the red bounding box a cylinder?", num_objects=1)
  # Create a new variable for the selection
  the_cylinder = is_cylinder("x1").iota("x1") 
  
  is_sphere = score("Is the main object in the red bounding box a sphere?", num_objects=1)
  the_spheres = is_sphere("x2").iota("x2")

  same_color = score("Is the main object in the red bounding box the same color as the main object in the green bounding box?", num_objects=2)

  # Use the selections in the relation
  cylinder_same_color_as_sphere = (
      the_cylinder("x1") & the_spheres("x2") & same_color("x1", "x2")
  )
  
  if cylinder_same_color_as_sphere.exists():
      return "Yes"
  else:
      return "No"
  ```


8. **Universal Quantification and Implication:**
   - **Universal Quantification (`forall`):**
     - **Purpose:** Check if a condition holds for *all* objects.
     - **Syntax:** `result = predicate.forall("x1")`
     - **Returns:** 
       - On a 1D predicate: A scalar score/boolean.
       - On a 2D relation (e.g., `R(x1, x2)`): A 1D tensor over the remaining variable.
     - **Important Note on Relations:** When applied to a square matrix (relation on the same set of objects), `forall` **ignores the diagonal** (self-relations). It checks if the condition holds for all *other* objects.
   
   - **Implication (`implies`):**
     - **Purpose:** Express logical implication (P ⇒ Q). Equivalent to `~P | Q`.
     - **Syntax:** `result = antecedent.implies(consequent)`
     - **Usage:** Often used with `forall` to check "Every X is Y".
     
   - **Example:** "Every red object is a circle"
     ```python
     is_red = score("...red?", num_objects=1)
     is_circle = score("...circle?", num_objects=1)
     
     # Check: For all x1, (is_red(x1) implies is_circle(x1))
     all_red_are_circles = is_red("x1").implies(is_circle("x1")).forall("x1")
     ```
9. **Comparisons:**
   - Use `>`, `<`, `==` to compare counts or other numerical values.
   - **Example:**
     more_apples = apple_count > orange_count
10. **Indexing with `argmax` and `topk`:**
   - **Purpose:** Find the indices of objects with high scores.
   - **argmax:**
     - **Syntax:** `index = result.argmax()`
     - **Returns:** A single Python `int` representing the index of the highest scoring object.
     - **Get the n-th highest index:** `index = result.argmax(k=n)` (Returns `int`)
   - **topk:**
     - **Syntax:** `indices = result.topk(k=n)`
     - **Returns:** A list of integers containing the top `n` indices.
   - **Restriction:** 
     - Never use `argmax` results for further composition with slicing and indexing. 
       *Incorrect:* `same_row_as_blue_circle = same_row[blue_circle.argmax(), :]`
       *Correct:* `same_row_as_blue_circle = same_row("x1","x2") & blue_circle("x2")`
11. **Variables:**
   - `objects_count` holds the total number of objects in the scene.
12. **Constraints:**
    - Do not rely on bounding box order; it is random.
    - Avoid using `for` loops except where needed for querying multiple objects.
    - Break down problems into the simplest possible steps.
    - Do not query multiple objects simultaneously without looping.
    - Do not use more arguments than shown in the examples.
    - When using `score`, make your questions as specific as possible.
    - If you combine more than two concepts use `and_op` or `or_op` with proper variables.
    - Don"t use equal sign and for the results of `query` since the output of `query` coming from an LLM can be undeterministic. 
    - If the question implies a specific number of objects (e.g., "the two cubes"), assume that number exists. Do not write code to validate the count or return error messages if the count differs. 
13. **Avoid Comparing Query Results Directly:**
    - Use `score` for concept comparisons rather than comparing string or numeric outputs from `query`.
    - **Example (checking if any two objects share the same color):**
      <code>
      # Check if main objects in red & green bounding boxes share the same color
      same_color = score("Is the main object in the red bounding box the same color as the main object in the green bounding box?", num_objects=2)
      # Check if there is at least one pair of objects with the same color
      return same_color.exists()
      </code>
    - **Do NOT do**:
      colors = [query("What is the color of the main object in the red bounding box?", object_id=i) for i in range(objects_count)]
      # then compare colors[i] to colors[j] in a loop
      or if query("What is the color of the main object in the red bounding box?") == "red". Use the `score` function for these comparison

<text>Which cat is just right of the cake?</text>
<type_of_reasoning>
Declarative only
</type_of_reasoning>
<steps>
1.  Score: Identify definite cats (target) → is_cat(x1) → iota(x2)
2.  Score: Identify cakes (reference) → is_cake(x2)
3.  Select (Iota): Normalize reference object score (cake) → iota(x2)
4.  Use Predefined: Check if x1 is right of x2 → right_of(x1, x2)
5.  Compose: Combine target, relation, and normalized reference → cat(x1) & right_of(x1, x2) & cake_score(x2)
6.  Select (Iota): Normalize target object score to 1D → iota(x1)
7.  Argmax: Find the index of the highest scoring cat → argmax()
8.  Query: Describe the identified cat → query(object_id)
<code>
is_cat = score("Is the main object in the red bounding box a cat?", num_objects=1)
is_cake = score("Is the main object in the red bounding box a cake?", num_objects=1)
is_cat = is_cat("x1").iota("x1")
is_cake = is_cake("x2").iota("x2")

# Compose and normalize target

cat_just_right_of_cake = (is_cat("x1") & right_of("x1", "x2") & cake_score("x2"))
cat_just_right_of_cake = cat_just_right_of_cake.iota("x1")

object_id = cat_just_right_of_cake.argmax()
return query("Describe the cat in the red bounding box", object_id=object_id)
```

<text>How many apples does the cat have in its paws?</text>
<type_of_reasoning>
Declarative only
</type_of_reasoning>
<steps>
1.  Score: Identify apples (target) → is_apple(x1)
2.  Score: Identify cats (reference) → is_cat(x2) → iota(x2)
3.  Score: Identify relationship → in_the_paws(x1, x2)
4.  Select (Iota): Normalize reference object score (cat) → iota(x2)
5.  Compose: Combine apple, relation, and normalized cat score → apple(x1) & in_the_paws(x1, x2) & cat_score(x2)
6.  Count: Count apples satisfying the predicate → count()
</steps>
```python

# 2. Define reference property (x2)
is_cat = score("Is the main object in the red bounding box a cat?", num_objects=1)

# 3. Define the relationship
in_the_paws = score("Is the main object in the red bounding box in the paws of the main object in the green bounding box?", num_objects=2)

# 4. Normalize the reference object "x2"
cat_score = is_cat("x2").iota("x2") # Select (Iota) for Reference
# 5. Compose the full predicate

apple_in_cats_paws = and_op(is_apple("x1"), in_the_paws("x1", "x2"), cat_score("x2")).exists("x2")

# 6. Count the number of apples (x1) that satisfy the predicate

return apple_in_cats_paws.count()
```

<text> Is the color of the frutherest cat black or white? <text>
<type_of_reasoning>
Declarative only
</type_of_reasoning>
<steps> 
1.  Score: Identify definite cats → is_cat(x) → iota(x)
2.  Score: Identify "furthest cat" (Tight Concept) → is_furthest_cat(x)
3.  Score: Identify black objects → is_black(x)
4.  Score: Identify white objects → is_white(x)

is_black = score("Is the main object in the red bounding box black?", num_objects=1)

furthest_cat_score("x1") = (is_cat("x1").iota("x1") & is_furthest_cat("x1")).iota("x1") 

furtherest_cat_black = furthest_cat_score("x1") & is_black("x1")
furtherest_cat_white = furthest_cat_score("x2") & is_white("x2")


if furtherest_cat_black.exists("x1") > furtherest_cat_white.exists("x2"):
    return "black"
else:
    return "white"
```



<text>What is the main object next to the cake that is front and center of the room?</text>
<type_of_reasoning>
Declarative only
</type_of_reasoning>
<steps>
1.  Score: Identify cakes (reference iota) → is_cake(x2) → iota(x2)
2.  Score: Identify center objects → is_center(x2)
3.  Score: Identify front objects → is_front(x2)
4.  Compose: Combine reference properties → cake(x2) & center(x2) & front(x2)
5.  Select (Iota): Normalize composite reference score (cake) → iota(x2)
6.  Use Predefined: Check closeness (next to) → closeness(x1, x2)
7.  Compose: Combine relation and normalized reference → closeness(x1, x2) & cake_score(x2)
8.  Select (Iota): Normalize target object score (x1) → iota(x1)
9.  Argmax: Find index of highest scoring object → argmax()
10. Query: Describe the object → query(object_id)
</steps>
```python
# 1. Define properties for the reference object (x2)
is_cake = score("Is the main object in the red bounding box a cake?", num_objects=1)
is_center_of_room = score("Is the main object in the red bounding box in the center of the room?", num_objects=1)
is_in_front = score("Is the main object in the red bounding box in front of the scene?", num_objects=1)
# 2. Compose and normalize the reference object "x2"
# This creates a 1D score for "cake that is front and center"

cake_score = (is_cake("x2").iota("x2") & is_center_of_room("x2") & is_in_front("x2")).iota("x2")  # Select (Iota) for Reference
# 3. Use the predefined "closeness" relation for "next to"
is_next_to = closeness
# 4. Create the full predicate: (target x1) is next to (reference x2)
