Instructions for Writing Programs Based on Scene Descriptions

You will be asked to write Python programs to answer questions about a visual scene. 
Use only the specified functions and adhere to the following guidelines.

--- Available Functions and Usage Guidelines ---

1. **Score Generation with `score`:**
   - **Purpose:** Determine if objects have certain properties or relationships.
   - **Returns:** Scores [0-1] for all objects in the scene for the question asked.
   - **Syntax:**
     \[
     result = score(question, num_objects)
     \]
   - **Parameters:**
     - **question (str):** The question to pose to the model.
     - **num_objects (int):** The number of objects involved (0 to 3).
       - **0:** A question about the entire scene. Returns a scalar value.
       - **1:** A question about the main object. If you use bounding box ask a question about the object in the red bounding box. Returns a 1D vector.
       - **2:** A question involving objects in the red and green bounding boxes. The red box is the reference object. Returns a 2D vector with an indentity mask which row[i][j] represents the object i (red bbox) has the relation with j (green bbox).
       - **3:** A question involving objects in the red, green, and blue bounding boxes. The red box is the reference object. Returns a 3D vector.

  2. **Precomputed Spatial Relations (use directly):**
     - Spatial relations are already provided as tensors in the runtime context: `left`, `right`, `front`, `behind` (also `above`, `below`, `distance`).
     - Use them directly as predicates, e.g. `left('x1', 'x2')` means object `x1` is left of object `x2`.
     - Do **not** define these spatial relations with `score(...)`.
     
3. **Querying with `query`:**
   - **Purpose:** Retrieve specific textual information about an object.
   - **Returns:** A string answer for the question mentioned in the query (It may include reference to the red bounding box). 
   - **Syntax:**
     \[
     answer = query(question, object_id)
     \]
   - **Parameters:**
     - **question (str):** The question to ask.
     - **object_id (int):** The identifier of the main object, typically obtained from `argmax()`. 
   - Warning: Since the output is undeterministic don't use string equality
   
4. **Composition Operations:**
   - Use `&` or `and_op` for logical AND, `|` or `or_op` for logical OR, and `~` for logical NOT. 
   - Do not use Python's `and` or `or` for probabilistic/score-based functions.
   - In composition you can assign **string** variables to predicates; the default variable for 1D predicate is `x1` and 2D predicates `x1`,`x2`.
   - **Composition Rules:**
     - 1D concept composed with a 1D concept returns a 1D vector of the composed concept.
     - 2D concept composed with a 1D concept returns a 2D vector of the composed concept.
     - For composing more than two predicates use the `or_op` or `and_op` function
   - **Examples:**
     <code>
     is_cat = score("Is the main object in the red bounding box a cat?", num_objects=1)
     same_shape = score("Is the main object in the red bounding box the same shape as the main object in the green bounding box?", num_objects=2)
     is_black = score("Is the main in the object red bounding box black color?", num_objects=1)

     is_black_cat = is_cat('x1') & is_black('x1')
     same_shape_as_black_cat = same_shape('x2','x1') & is_black_cat('x1')
     ## OR
     same_shape_as_black_cat = and_op(same_shape('x2','x1'), is_cat('x1'), is_black('x1'))
     </code>
   - **Important:** 
     - Do not use `argmax` and indexing for composing relationships with properties.
     - If you already used a concept in a `query` function, do not compose it again with the results of that same query. 
       (e.g., avoid: `apple_behind_large_pineapple & is_large_pineapple` → separate them properly).

   - **Another example:**
     <code>
     # "blue circle same size as a red circle"
     blue_circle = is_blue & is_circle # Or is_blue('x1') & is_circle('x1')
     red_circle = is_red & is_circle # Or is_red('x1') & is_circle('x1')
     same_size_as_red_circle = same_size & red_circle # Or same_size('x1','x2') & red_circle('x2')
     blue_circle_same_size_as_red_circle = same_size_as_red_circle & blue_circle # Or same_size_as_red_circle('x1','x2') & blue_circle('x1')
    </code>

5. **Existence and Counting:**
   - To check if any object satisfies a predicate, use .exists(). Example: is_red.exists()
   - To check if any object along a specific variable satisfies a condition, use exists with only one variable such as `.exists('x1')` or `.exists('x2')`. Example: (is_blue('x2') & left_of('x2', 'x1')).exists('x2')
   - To check if all objects satisfy a predicate, use .forall('x1') or .forall('x2'). Example: is_red.forall('x1')
  - Combine .forall() with implication to express universal quantification. Example: red = score("Is red?", num_objects=1) blue = score("Is blue?", num_objects=1) result = red('x1').implies((blue('x2') & left('x2', 'x1')).exists('x2')).forall('x1')
   - Use .count() to count how many objects match a predicate: count = is_cat.count() count_per_object = same_shape.count('x1') or same_shape.count('x1', 'x2')
   - You can compare counts using >, <, ==. Example: more_red = is_red.count() > is_blue.count()
   - **Count occurrences:**
     <code>
     counts = is_cat.count() # returns the number of cats
     counts = is_cat.count('x1') # return a 1D vector with 1 where object 'i' is a cat
     counts = same_shape.count() # returns a total number of objects that have the same shape (it's the value times 2 if the relation is symmetric)
     counts = same_shape.count('x1') # return a 1D vector with the number of object with the same_shape as object `i`
     counts = same_shape.count('x1', 'x2') # returns a 2D matrix of if `i` is in the same shape as `j`
     </code>
   - You can compare counts using >, <, ==. Example: more_red = is_red.count() > is_blue.count()

     
6. **Comparisons:**
   - Use `>`, `<`, `==` to compare counts or other numerical values.
   - **Example:**
     more_apples = apple_count > orange_count
     

7. **Indexing with `argmax`:**
   - **Purpose:** Find the index of the main object with the highest score.
   - **Syntax:**
     index = result.argmax()
     
   - **Get the n-th highest index:**
     index = result.argmax(k=n)
   - Get the top-k indices
     topk = result.topk(k=1,dim=-1)
   - **Restriction:** 
     - Never use `argmax` results for further composition with slicing and indexing. 
       *Incorrect:* `same_row_as_blue_circle = same_row[blue_circle.argmax(), :]`
       *Correct:* `same_row_as_blue_circle = same_row("x1","x2") & blue_circle("x2")`

    
8. **Variables:**
   - `objects_count` holds the total number of objects in the scene.

9. **Looping and Iteration:**
   - Only use loops for querying multiple objects.
   - **Example:**
     colors = [query("What is the color of the main object in the red bounding box?", object_id=i)
               for i in range(objects_count) if is_apple[i]]

10. **Constraints:**
    - Do not rely on bounding box order; it is random.
    - Avoid using `for` loops except where needed for querying multiple objects.
    - Break down problems into the simplest possible steps.
    - Do not query multiple objects simultaneously without looping.
    - Do not use more arguments than shown in the examples.
    - When using `score`, make your questions as specific as possible.
    - Never use `score` to model spatial relations like left/right/front/behind; use the precomputed relation tensors directly.
    - If you combine more than two concepts use `and_op` or `or_op` with proper variables.
    - Don't use equal sign and for the results of `query` since the output of `query` coming from an LLM can be undeterministic. 
11. **Avoid Comparing Query Results Directly:**
    - Use `score` for concept comparisons rather than comparing string or numeric outputs from `query`.
    - **Example (checking if any two objects share the same color):**
      <code>
      # Check if main objects in red & green bounding boxes share the same color
      same_color = score("Is the main object in the red bounding box the same color as the main object in the green bounding box?", num_objects=2)
      # Check if there is at least one pair of objects with the same color
      return same_color.exists()
      </code>
    - **Do NOT do**:
      colors = [query("What is the color of the main object in the red bounding box?", object_id=i) for i in range(objects_count)]
      # then compare colors[i] to colors[j] in a loop
      or if query("What is the color of the main object in the red bounding box?") == "red". Use the `score` function for these comparison

<text> If an object is a cake, then there exists a sweet object to its left.</text>
<steps>
1. Score: Identify cakes → is_cake(x1)
2. Score: Identify sweet objects → is_sweet(x2)
3. Score: Check left_of(x2, x1) (green left of red)
4. Compose: sweet(x2) ∧ left_of(x2, x1)
5. Existential quantifier over x2: ∃x2 (sweet ∧ left_of)
6. Implication: is_cake(x1) ⇒ ∃x2 (...)
7. Universal quantifier over x1: ∀x1
</steps>
<code>
is_cake = score("Is the main object in the red bounding box a cake?", num_objects=1)
is_sweet = score("Is the main object in the red bounding box sweet?", num_objects=1)

# ∃x2: sweet(x2) ∧ left_of(x2, x1)

# ∀x1: is_cake(x1) ⇒ ∃x2 (...)
implication = is_cake('x1').implies(sweet_left)

return implication.forall('x1')
</code>
